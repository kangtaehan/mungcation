# iOS 검증 상태와 실행 절차

## 확인한 범위

2026-11-12 Windows + Flutter 3.41.9 / Dart 3.11.5 환경에서 확인했습니다.

- 의존성 설치: 성공.
- `flutter analyze`: 오류·경고 없음.
- Flutter 자동 테스트: 기존 38개를 포함한 49개 통과, Android 사진 복구 추가 테스트 1개 통과. Android 변경 범위는 ANDROID_VALIDATION.md 참고.
- 앱 아이콘·시작 이미지·꾸미기 방 렌더링: 4개 통과. `artifacts/room_preview.png` 시각 확인.
- 네이티브 파일의 plist·XML·아이콘 규격과 프로젝트 참조: 정적 확인.
- **Swift 컴파일·XCTest·시뮬레이터·iPhone: 미실행.** Windows에는 Xcode/iOS SDK가 없습니다.

테스트 위치 공급자는 제어된 샘플이며 MapKit 응답 테스트는 MethodChannel 대역입니다. 사진 필터·백업 이미지 검증·JSON 저장·삭제·내보내기 임시 파일 정리는 실제 로컬 파일로 확인했습니다. 공유·선택 화면은 테스트 대역으로 확인했으며 iOS UIActivityViewController·UIDocumentPicker 실행은 미확인입니다. 따라서 실제 GPS 정확도·배터리·잠금 화면·네트워크·장소 데이터 품질을 입증하는 결과는 아닙니다.

## 자동 테스트 재실행

일반 경로:

```sh
flutter pub get
flutter analyze
flutter test --concurrency=1
```

Windows 한글 경로의 엔진 실행 문제를 피하려면:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tool/test_windows.ps1
```

이 스크립트는 소스를 영문 임시 경로에 복사하고 TEMP/TMP를 바꿔 테스트합니다. 결과 재현을 위해 임시 폴더를 유지하고 경로를 출력합니다. 원본 소스를 삭제하거나 변경하지 않습니다.

아이콘·방 렌더링 재생성:

```sh
flutter test tool/render_brand_assets_test.dart --concurrency=1
```

이 명령은 프로젝트의 iOS 아이콘·시작 이미지와 `artifacts/room_preview.png`를 갱신합니다.

## Mac에서 먼저 실행할 작업

```sh
bash tool/verify_ios.sh
open ios/Runner.xcworkspace
```

1. Xcode에서 Runner 스킴을 선택하고 iPhone 시뮬레이터를 대상으로 빌드합니다. 이 단계에서 Swift 브리지·등록·플러그인 문제를 확인합니다.
2. `Product > Test`로 `RunnerTests`의 네이티브 입력 검증 7개를 실행합니다.
3. 실제 iPhone 실행에는 개발 팀과 고유 Bundle Identifier를 설정합니다. 현재 임시 값은 `com.mungcation.mungcation`입니다.

| 권한 거부 | 위치 거부·영구 거부·위치 서비스 꺼짐에서 기록 시작 차단과 설정 안내 |

| 앱 전환 | 기본 설정에서 백그라운드 진입 시 자동 일시정지 |

| 장소 | 실제 검색 결과와 동반 조건 미확인 문구, Apple 지도에서 열기 |
| 방문 | 정확한 위치·반경·체류 확인 후 자동 인증, 동일 산책 중복 없음, 하루 보상 한도 |
| 사진 | 실제 카메라·갤러리·취소·권한 거부·선택·저장·재실행·변경·삭제 |

## 남은 외부 연결

- 사진 기반 실제 AI 생성: 미연결. 합의한 기기 내 사진 필터가 현재 대안입니다.
- 안전 우선 경로: 인도·횡단보도 데이터 미연결. 모든 MapKit 경로는 인도 미확인입니다.
- 검증된 반려견 동반 정책: 공식 장소 데이터 또는 매장 확인 정보 미연결.
- 서버 보상 검증·계정 동기화·App Store 서명 및 배포: 미연결.

위 항목과 iOS 네이티브 실행을 확인하기 전에는 출시 완료로 간주하지 않습니다.
